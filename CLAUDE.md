# CLAUDE.md

Страницы, приложение для iPhone, модули и правила виджетов описаны в README.md («Веб-интерфейс», «Приложение для iPhone», «Устройство»). Прочитай нужный раздел, прежде чем менять страницу, экран или модуль.

## Общение

- Пользователь пишет по-русски, отвечай тоже по-русски. Код, комментарии и коммиты пиши по-английски, тексты интерфейса и README — по-русски.
- Дорожной карты нет: следующий шаг пользователь выбирает сам, глядя на свои данные. Поэтому отчёт заканчивается сделанным, без «дальше предлагаю…».
- Отчёт строй так: что сделано и где посмотреть (URL с портом или «на iPhone»), затем «Решения, которые я принял сам», что заметил в реальных данных и что нужно от пользователя.
- Если правило предметной области меняет расчёт (формула аванса, какие траты идут в неделю), спроси через AskUserQuestion с вариантами. Остальное решай сам и перечисли в отчёте.

## Worktree и данные

- Основная копия `~/orca/projects/budget17` — это ветка `main`, там же `.env` с токеном, настоящие базы в `data/` и сервер пользователя `make web` на порту 4317.
- Каждая задача идёт в своём worktree `~/orca/workspaces/budget17/<задача>`, где нет ни `.env`, ни `data/`.
  - Токен подключай по пути, без копирования: `node --env-file=/Users/kir/orca/projects/budget17/.env …`.
  - Если проверка что-то записывает (формы, тестовые записи), работай на копии: `mkdir -p data && cp ~/orca/projects/budget17/data/*.db data/`.
  - Если пользователь должен увидеть свою настоящую картину, сделай symlink `data` → `~/orca/projects/budget17/data`. Правило `data/` из `.gitignore` symlink не ловит, поэтому добавь `/data` в `$(git rev-parse --git-common-dir)/info/exclude`.
  - Скрипт, который открывает `Store` или `Settings` в worktree без `data/`, создаёт пустые базы, и сервер начинает показывать пустоту вместо демо. Разовые скрипты держи в scratchpad, пути к базам основной копии указывай явно и открывай базы только на чтение (`sqlite3 -readonly`, `{ readOnly: true }`).
- `~/orca/projects/budget17/data/settings.db` хранит то, что пользователь ввёл сам: регулярные траты, доходы, план, разметку. Меняй его только по просьбе пользователя, а записи, созданные для проверки, удаляй.
- В ZenMoney ничего не пишем, хотя токен это позволяет. Своё храним в `settings.db`, а категория, выбранная в приложении, важнее категории из ZenMoney.
- Прежде чем проектировать логику, посмотри на реальные данные разовым скриптом. Там переводы людям записаны как расходы (недели выходят от 75 до 525 тыс.), у многих трат нет категории, а регулярные платежи приходят на 6–8 дней раньше срока. Логика, построенная на демо-данных, на настоящих ломается.

## Интерфейс

- Экран отвечает на практический вопрос (сколько ещё можно потратить, когда покупать): несколько блоков, а не вся модель. Правила и пограничные случаи объясняй в сообщении, а не на странице.
- Прототип веб-страницы, даже прототип логики, делай внутри приложения: настоящий маршрут, `?variant=` с плавающим переключателем, только виджеты из `src/web/widgets`, реальные данные, состояние в памяти. Отдельную HTML-страницу со своим оформлением пользователь отверг. Выбранный вариант переписывается начисто, а прототип коммитится в ветку `prototype/<тема>` и в `main` не попадает.
- Схему `settings.db` меняй только добавлением колонок: их список лежит в `ADDED_COLUMNS` в `src/settings.ts`, и при открытии базы они добавляются через ALTER TABLE. Проверяй тестом на базе старого формата.

## Приложение для iPhone

- Пользователь живёт в приложении на своём iPhone «Pepelatz», веб — для настройки. Приложение — тонкий клиент: суммы, подписи и правила считает сервер в `src/web/api.ts` теми же функциями, что и страницы, а Swift только раскладывает JSON. Меняешь то, что говорит страница, — проверь, что API говорит то же.
- В приложении только цифры: без поясняющих фраз веба, без счёта списания и времени в карточках, без подписей, которые и так понятны. Устройство экрана (сводка на белом, тёмная полоса с пилюлями, лист карточек с заголовками дней) пользователь выбрал по своему референсу; новые экраны собирай из `ios/Budget/Design.swift`.
- Телефон смотрит на сервер `make web` пользователя: `http://MacBook-Pro-kir.local:4317`. Пока изменение API не в `main`, телефону нужен сервер worktree: подними его на 4318 с symlink `data` и попроси пользователя сменить адрес (Ещё → шестерёнка → Выйти, войти с `:4318`); после мержа — вернуть `:4317`.
- После правок приложения ставь его на телефон: `make ios-install`. Заблокированный телефон приложение ставит, но не открывает, — так и скажи пользователю. С бесплатным Apple ID подпись живёт 7 дней, переподписывает та же команда.
- Смотри приложение в симуляторе: `ios/screens.sh http://localhost:4318 <scratchpad>/shots` проходит все экраны и лист траты, читай скриншоты. Он только открывает и закрывает, поэтому годится для настоящих данных.
  - Нажатия в разметке проверяет `testMarking`, он меняет данные: подними сервер с копией баз — скопируй `src` и `package.json` в папку scratchpad, сделай `sqlite3 -readonly <база> ".backup '<копия>'"` для обеих баз в её `data/`, запусти `PORT=4319 node src/web/server.ts` без токена — и гоняй тест с `TEST_RUNNER_MARKING=1 TEST_RUNNER_SERVER=http://localhost:4319` (команда — как в `ios/screens.sh`, с `-only-testing:BudgetUITests/ScreensTests/testMarking`).
  - Вид виджета рисуй на Mac: `ImageRenderer` в пакете из scratchpad с копией `ios/BudgetWidget/BudgetWidget.swift` (без `@main` и `accessory`-размеров, `Link` заменить на `Group`) и `ios/Shared`.
- Xcode установлен, но `xcode-select` указывает на Command Line Tools: скрипты ставят `DEVELOPER_DIR` сами, свои `xcodebuild` и `xcrun` запускай с `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`.
- Симулятор iOS качай одной командой, `xcodebuild -downloadPlatform iOS`. Дубли образов оставляй как есть: `simctl runtime delete` стирает и общий файл рабочего образа.
- В цели приложения всё по умолчанию на главном акторе (Swift 6). Замыкание, которое система зовёт с другого потока, объявляй `nonisolated` и `@Sendable`, как `Color(light:dark:)` в `ios/Shared/Format.swift`; иначе приложение падает в `_dispatch_assert_queue_fail`. Виджет собирается в режиме Swift 5.
- Виджет берёт адрес сервера и токен из общей связки ключей `BSTT86K4F6.ru.apukhtin.budget` (entitlements обеих целей), App Group нет. Данные виджета — `/api/widget`.
- Сервер на VDS ещё не развёрнут: пользователь решил сначала проверить всё дома. `deploy/deploy.sh` на настоящем сервере не запускался. Когда пользователь даст `root@адрес`, спроси подтверждение перед `--data`: оно увозит его базы с Mac.

## Проверка

- Запускай `make check` перед каждым отчётом и перед мержем. В него входит `make ios-check`: модели приложения читают JSON всех экранов, код собирается под симулятор.
- Свой сервер поднимай в фоне на порту 4318 или выше: `PORT=4318 node src/web/server.ts`. Порт 4317 занят сервером пользователя.
  - Сервер держит модули в памяти, после правок его нужно перезапускать.
  - В конце останови свой сервер по его task или PID: `pkill` по шаблону может задеть сервер на 4317.
- Проверяй веб глазами: снимай скриншоты в scratchpad на ширине 1440 и около 400 и читай их.
  - Статичная страница: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --hide-scrollbars --window-size=1440,1300 --screenshot=<scratchpad>/x.png <url>`.
  - Клики и формы: Playwright из кэша npx (`ls ~/.npm/_npx/*/node_modules/playwright/index.mjs`).
  - POST через curl отправляй с `-H "Origin: http://localhost:<порт>"`, иначе сервер отклонит запрос.
- В начале месяца текущий месяц почти пустой, поэтому смотри и прошлый (`?month=…`).
- `money()` вставляет неразрывный пробел (U+00A0) внутрь сумм и перед символом валюты. Тесты страниц поэтому прогоняют HTML через `.replaceAll(' ', ' ')`. Замена по тексту с обычным пробелом в файлах, где есть U+00A0, молча ничего не находит.
- У пользователя валюта называется «руб.», так что фраза, которая кончается суммой, получает двойную точку.

## Мерж

- `main` двигается только по слову пользователя («мержи», «смержи»). Порядок такой:
  1. `make check`.
  2. Коммит в ветку worktree в стиле `git log`: повелительный заголовок, тело — прозой о поведении, строки интерфейса в «». В тот же коммит идёт README: страница в «Веб-интерфейс», экран в «Приложение для iPhone», модуль в «Устройство», пункт в «Сделано».
  3. `git -C ~/orca/projects/budget17 status --short` должен вернуть пустой вывод.
  4. `git -C ~/orca/projects/budget17 merge --ff-only <ветка>`. Удалённого репозитория нет, push не нужен.
- После мержа попроси пользователя перезапустить `make web`: сервер на 4317 работает со старым кодом.
- Если пользователь пишет «не вижу» или «не работает», сначала выясни, какой сервер и какой код он смотрит; на телефоне — какой адрес стоит в приложении и когда его ставили (`make ios-install`).
