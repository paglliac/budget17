# Бюджет

Приложение для учёта домашних финансов. У Т-Банка нет публичного API, поэтому данные берём из [ZenMoney](https://zenmoney.ru): он синхронизируется с банком, а мы читаем его через [ZenMoney API v8](https://github.com/zenmoney/ZenPlugins/wiki/ZenMoney-API).

## Быстрый старт

1. Node.js ≥ 24: TypeScript запускается напрямую, сборка не нужна.
2. `make install`
3. Получите токен: откройте <https://zerro.app/token>, войдите через ZenMoney и скопируйте токен.
4. `cp .env.example .env` и вставьте токен в `ZENMONEY_TOKEN`.
5. `make balances`

Токен даёт полный доступ к данным ZenMoney, включая запись. `.env` уже добавлен в `.gitignore`.

## Команды

`make` без аргументов показывает список.

| Команда          | Что делает                                         |
| ---------------- | -------------------------------------------------- |
| `make sync`      | Загрузить изменения из ZenMoney в локальную базу   |
| `make balances`  | Синхронизация, затем счета и итоговый баланс       |
| `make web`       | Веб-интерфейс на <http://localhost:4317>           |
| `make claude-review` | Claude по подписке разбирает месяц (см. «Разбор месяца с Claude») |
| `make resync`    | Удалить копию ZenMoney и скачать всё заново        |
| `make pull-data` | Базы сервера <https://budget.gang.su> в `data/` этой копии (см. «Сервер в интернете») |
| `make check`       | Тесты, проверка типов и `make ios-check`           |
| `make ios-check`   | Приложение для iPhone собирается и читает JSON API |
| `make ios-install` | Поставить приложение на iPhone, раз в 7 дней — переподписать |
| `make install`     | Установить зависимости                             |

Makefile вызывает npm-скрипты из `package.json`, их можно запускать и напрямую: `npm run sync`, `npm run balances`, `npm run web`, `npm test`, `npm run typecheck`.

## Синхронизация

Данные хранятся локально в SQLite: `data/zenmoney.db` (встроенный `node:sqlite`, папка в `.gitignore`).

- Первый запуск скачивает всё (около 2 МБ, 1–2 с), следующие — только изменения после сохранённого `serverTimestamp` (обычно десятки байт, ~150 мс).
- В изменения попадают и правки старых операций, а удаления приходят отдельным списком `deletion`, так что перечитывать историю не нужно.
- Изменения применяются в одной транзакции: если запись сорвалась, база остаётся в прежнем состоянии, и следующий запуск повторит загрузку.
- Сущности хранятся JSON-ом в том виде, в каком их отдаёт API, поэтому новые поля ZenMoney не требуют миграций.
- То, что настраивается в самом приложении (план недель, желания с их сроками и выбранными планами, разметка трат и доходов: категории, подкатегории, привязки к регулярным тратам, покупкам и желаниям, — списки категорий, доходы, регулярные траты, день начала недели и суммы отдельных недель), лежит отдельно, в `data/settings.db`, поэтому `make resync` его не трогает.

## Свежесть данных

API отдаёт только то, что уже есть в ZenMoney, и не умеет запускать синхронизацию с банком. Для Т-Банка её выполняет приложение ZenMoney на телефоне: по расписанию из настроек подключения (у нас — раз в 20 минут; на iPhone фоновый запуск дополнительно решает iOS) или вручную. После ручной синхронизации в приложении операции появляются в API через несколько секунд.

## Веб-интерфейс

`make web` запускает сервер на <http://localhost:4317> (порт меняется переменной `PORT`). Слева на каждой странице — панель разделов; шар вверху неё ведёт на `/`.

- `/` — бюджет неделями: 45 000 ₽ в неделю на обычные траты и 100 000 ₽ в месяц на дополнительные (лимиты пока заданы в `src/week.ts`, сумму отдельной недели меняют на её странице). Неделя начинается в день, выбранный в настройках, по умолчанию в понедельник, и относится к месяцу, на который приходится больше её дней, то есть её четвёртый день (у недели с понедельника — четверг). Если у недели своя сумма, она стоит вместо 45 000 ₽ в остатке, в подписи «из 30 000 ₽ на неделю» и в итоге месяца, а под заголовком недели написано, что её бюджет изменён.
  - Вкладка «Неделя» показывает траты недели из ZenMoney по дням: название, счёт и категория в строке, точка перед суммой говорит, где трата считается. Сбоку, в широкой колонке, — сколько ещё можно потратить, «Бюджет недели», план недели и «Хочу купить». «Бюджет недели» — сколько неделе можно потратить: «как обычно» 45 000 ₽ или своя сумма «вместо 45 000 ₽». Строка открывает форму: другая сумма, например 30 000 ₽, когда что-то случилось и неделе нужно ужаться, или «Вернуть 45 000 ₽». Так меняют и будущую, и прошедшую неделю; 45 000 ₽ своей суммой не считается. План — это покупки и регулярные траты недели (они вне бюджета); у них тоже точка: жёлтая — из недели, фиолетовая — из дополнительных, пустое кольцо — вне бюджета. Регулярная трата, которую закрыли привязанные к ней траты, помечается галочкой и «оплачено 5 октября», даже если её оплатили на неделю раньше; если привязанных не хватает до суммы, видно, сколько из неё оплачено. Траты, привязанные к покупке, вычитаются из плана: у «Продуктов» на 3 000 ₽ после траты в 473 ₽ в плане остаётся 2 527 ₽ и написано «оплачено 473 ₽ из 3 000 ₽», а когда траты покрыли сумму, покупка становится «куплено 5 октября». Галочка «Завершить», которая появляется при наведении на покупку (на телефоне — кнопка в её форме), закрывает покупку, не дожидаясь полной суммы: за ней остаются только привязанные траты, а остаток плана возвращается в свободные («завершено, вернулось 2 527 ₽»). У купленной и завершённой покупки вместо плана видно, во что она обошлась; вернуть её в план можно из её формы. Под планом «Хочу купить»: для каждого желания написано, когда его можно купить — на этой неделе, в первую неделю, где хватает свободного, или из дополнительных. Кнопка «Запланировать» ставит желание в план этой недели. Желание, у которого в приложении выбран план (см. «Приложение для iPhone»), пишет срок и откуда деньги — «к 1 ноября · по 5 000 с 3 недель, 45 000 из дополнительных октября», — и «Запланировать» у него нет; деньги, которые держит его план, стоят в плане недели и в дополнительных строками «Резина Танюшке · отложить» с подписью «Желание» и без формы: план выбирают и меняют в приложении. Желание, которое купила трата, из «Хочу купить» уходит, а его строки становятся «Желание · куплено». Новую покупку и желание добавляют строками «Добавить в план» и «Добавить желание»: они раскрывают форму, «Отмена» сворачивает её. Трату размечают так же, как на `/uncategorized` (см. ниже «Разметка траты»). Покупку можно открыть, исправить, перенести в другую неделю или в дополнительные. У покупки есть тип: «Гибкая» — её можно перенести, или «Обязательная» — лучше не трогать, как стрижка, записанная на пятницу; его выбирают в форме покупки, а новые покупки и запланированные желания гибкие. Тип нужен приложению: на главной зарезервированное делится на обязательное и гибкое.
  - «← Раньше» и «Позже →» листают недели, вперёд — до года (`?week=2026-10-19`). В будущую неделю ставят то, что уже известно, например стрижки: трат у неё ещё нет, поэтому её план стоит в основной колонке, а сбоку — сколько будет свободно. Галочка «Завершить» у таких покупок появляется, когда неделя начнётся или к покупке привяжут трату.
  - Вкладка «Месяц» (`?view=month`) показывает недели месяца с итогом каждой и дополнительные: запланированные покупки и перенесённые траты. Месяцы листаются так же, до года вперёд (`?month=2026-11`); у будущей недели видно, сколько в её плане и сколько свободно. Любая неделя открывается по ссылке, а дополнительная покупка будущего месяца попадает в его первую неделю.
- `/review` — разбор месяца: что произошло с деньгами и что поправить. По умолчанию открывается прошлый месяц, вкладки сверху — текущий и два прошлых (`?month=2026-09`). Месяц — это его недели, как на обзоре. Сверху доход (без того, что «Не учитывается»), потрачено и что осталось (или «Не хватило»), под ними «Куда ушли деньги» с потраченным в правом верхнем углу: доход растекается на недели, регулярные, дополнительные, вне бюджета и остаток, с долей каждого. Лента каждой части приходит к своей строке и не задевает соседние, а большая часть делает график выше.
  - «Из чего недели» — траты недель плитками по сумме. Категории своим цветом, внутри — подкатегории, а у категории без них получатели; мелкие собраны в «Ещё 24», которая открывается своим списком. Траты, которые считаются в неделях, а что это — непонятно, заштрихованы: «Переводы людям» (получатель вида «Татьяна А.» без категории), «Переводы себе» (на имя из настроек) и «Без категории». Переводы себе разложены по сумме: «Похоже на Ozon и WB», «Сумма «Кредит Kia K5»» и «Круглые суммы». Lenta-0089, Lenta 178 и Лента-0089 — один получатель: название переводится в латиницу, номер магазина отбрасывается, а й, ы и я, которые банки пишут каждый по-своему, сводятся к одному, так что «Московский», MOSKOVSKIJ и Moskovskiy — тоже один. Переводы на номер карты различаются по номеру.
  - Плитка открывается сбоку (`?tile=`), повторный клик её закрывает, а «← К выводам» возвращает ассистента; на телефоне открытое встаёт сразу под своей группой. Сбоку — сумма и доля недель, подсказки про плитку, из чего она состоит и куда деть её траты. «Категория этих 7 трат» переносит в другую категорию только эти траты, правилом это не становится: следующие траты получателя без категории получат её подсказкой «по прошлым тратам». «Подкатегория» и «Новая подкатегория» кладут траты в подкатегорию. Подкатегорию магазина задают получателю: все его траты в этой категории, и новые тоже, идут туда сами. У перевода подкатегория своя у каждой траты. Отдельная трата открывается со своей категорией и подкатегорией и ссылкой «Вся разметка траты →», у подкатегории сбоку её получатели, название и «Удалить», у заштрихованной группы — «Разметить по одной →» на странице «Проверить».
  - Подсказки считаются правилами. Перевод или трата без категории — туда, куда ушли хотя бы две трети прошлых трат того же получателя («по прошлым тратам»). Перевод в категории с подкатегориями — в подкатегорию, куда так же шли его прошлые переводы. Переводы себе с некруглой суммой — туда, куда шли такие переводы раньше, в подкатегорию «Ozon и WB». Категория, в которой три месяца нет трат, — «Скрыть» (своя — только если в ней уже что-то было). На карте у группы с подсказкой точка, у её части — сиреневая рамка; сами подсказки стоят у плитки и сбоку под выводами. «Перенести» и «Скрыть» применяют подсказку один раз, правилом на будущее она не становится; «Не надо» убирает её насовсем.
  - «Недельные траты» — столбики недель против их лимитов: пунктир — лимит, выше него столбик темнее, бейдж — на сколько недели превысили план; столбик ведёт на неделю. «Регулярные платежи» — все регулярные траты, у которых в месяце срок, по дате: оплаченные с галочкой, суммой и днём привязанных трат, остальные — со сроком и суммой по плану, серые, если срок прошёл, и бирюзовые, если впереди; сверху — «оплачено 5 из 12». Привязанная трата засчитывается месяцу, в неделях которого прошла, даже если срок у платежа в другом: «Школа Первых» на 30-е, оплаченная 10 сентября, оплачена в сентябре.
  - Сбоку ассистент: карточка с тем, кто и когда разобрал месяц, чипы «Где перерасход и почему», «Какие траты проверить», «На чём сэкономить» и «План на следующий месяц» — они открывают ответ (`?ask=…`) со ссылками на траты — и вкладки «Выводы», «Подсказки» (`?list=hints`) и «Лишние траты» (`?list=spare`) с числом в каждой. Пока Claude месяц не разбирал, всё это считают правила: карточка «Разобрал сентябрь» с кнопкой «Попросить Claude», «Главные выводы» — недели больше плана и какая потратила больше всех, сколько трат непонятно что, переводы людям с крупнейшим, переводы себе и сколько из них похожи на покупки на Ozon и WB, категория, которая выросла больше чем на пятую часть и на 2 000 ₽ в неделю, нетронутые дополнительные; «Лишних трат» нет.
  - Когда Claude разобрал месяц (см. «Разбор месяца с Claude»), карточка — «Claude разобрал сентябрь», «9 октября в 19:45 · 5 выводов, 12 подсказок» и сколько трат пришло с тех пор, с кнопкой «Пересмотреть»; выводы, ответы на чипы и «Лишние траты» — его. В «Подсказках» сначала вопросы Claude с вариантами ответа кнопками («70 000 Татьяне А. 18 сентября — что это?» — «Обычная трата недели», «В дополнительные», «Вне бюджета»), потом его разметка («Нетмонет → «Кафе и рестораны»» с «Принять» и «Не надо») и разбиения категорий на подкатегории («Разбить» и «Не надо»), потом подсказки правил, кроме тех, чьи траты все уже есть у Claude. Траты, о которых Claude что-то сказал, отмечены на карте, как подсказки, а у открытой плитки его слова о ней стоят в «Claude об этом».
  - Сам Claude ничего не меняет: всё применяется по нажатию и только к названным тратам. «Принять» и ответ на вопрос ставят категорию, подкатегорию и где трата считается, как перенос на карте; «Разбить» создаёт подкатегории, магазины кладёт в них навсегда, а переводы месяца — по одному. Что сделано с подсказкой Claude — принято, «Не надо» или ответ, — хранится у траты и категории, поэтому следующий разбор этого не вернёт. Трату, которую с тех пор разметили по-своему, Claude больше не трогает. «Пересмотреть» просит Claude разобрать месяц заново с разметкой, описаниями трат и ответами: пока нового ответа нет, карточка пишет «Пересматриваю с 21:14» и даёт «Отменить», а новый ответ заменяет старый.
- `/review/check` — «Проверить» одну группу за раз (`?kind=person|self|untitled`), его открывают сбоку заштрихованной группы карты и из выводов ассистента: траты по дням, новые сверху, вкладки групп с числом трат и «← К разбору», сбоку сколько всего ждёт проверки. Трата раскрывается на месте и размечается как везде, а получив категорию, уходит из группы. У перевода себе банк неизвестен, поэтому в строке подсказка по сумме: «сумма «Кредит Kia K5»», если она равна регулярной трате, или «похоже на Ozon или WB» для некруглой суммы до 20 000 ₽.
- `/operations` — операции месяца по дням с фильтрами по виду, категории и тексту (`?kind=expense&category=…&q=кофе`) и расходами по категориям сбоку; с фильтром «Доходы» сбоку доходы по категориям. Переводы между своими счетами одного банка (у счетов один `company` в ZenMoney) не показываются ни здесь, ни в тратах: деньги просто лежат в другом месте. Переводы между банками и в наличные остаются. Расход открывается на месте и размечается так же, как на обзоре, доход — так же, но проще (см. «Разметка дохода» ниже); не учитываемые траты и доходы видны только здесь, бледными и вне сумм. Если в месяце есть необязательные траты, под заголовком написано, сколько на них можно было сэкономить, а среди видов появляется «Необязательные» (`?kind=optional`): только они, «5 необязательных трат на 6 880 руб.: столько можно было сэкономить», и сбоку «Необязательные по категориям».
- `/uncategorized` — траты месяца, пришедшие из ZenMoney без категории. Для части трат есть подсказка, её принимают кнопкой «Принять»: регулярная трата, которую этот получатель уже оплачивал той же суммой; регулярная трата той же суммы, до платежа которой не больше 10 дней; категория, которую получатель получает чаще всего (номера магазинов не важны: Lenta 089 и Lenta 139 — один магазин); регулярная трата, которую получатель оплачивал суммой в пределах 10%. Платёж, уже закрытый другой тратой, не предлагается. Трата, привязанная к регулярной трате или покупке, считается разобранной. Ниже — «Разобрано»: это можно поменять, отвязать или убрать категорию.
- Разметка траты одинакова на `/uncategorized`, на обзоре и в операциях: трата раскрывается на месте, страница не прыгает в начало, и выбор делается одним нажатием. Сверху — что известно о трате: дата и время (из ZenMoney, по банку), сумма с копейками, счёт, название у банка («В банке»), если ZenMoney, ты или известная сеть назвали получателя иначе, комментарий банка, сумма в валюте и «банк ещё не провёл».
  - Траты и доходы называются магазином, а не тем, как его пишет банк: все траты, которые банк называет Lenta-0089, Lenta-0178, LENTA 089PQR или «Лента», — один магазин «Лента», и в строке у него значок Ленты вместо иконки категории. Номер магазина и пометка оплаты по QR или СБП (…PQR, …SBP, и обрезанная банком — …PQ, …SQR, …PSBP) не важны, а все магазины одной сети — один магазин: SAMOKAT и SBER*5411*SAMOKAT — оба «Самокат», шесть разных записей Магнита — один «Магнит». 47 сетей — Лента, Бегемаг, Мария-Ра, Ярче, Пятёрочка, Магнит, Самокат, Яндекс Еда, Go и Такси, Ozon, Wildberries, Авито, Лукойл, Газпромнефть, МТС, Т-Мобайл и другие — называются по-русски сами. У частых магазинов — и сетей, и кемеровских мест вроде «Хлеба из тандыра» или «Птичьего двора» — значок приходит с приложением: круглый или эмблема на прозрачном фоне, найденный по картинкам в интернете (`src/shop-logos`), так что он одинаковый на Mac и на телефоне. У остальных сетей значок — значок их сайта: сервер берёт его у сервиса значков Яндекса (`favicon.yandex.net`) один раз и хранит; сайт без значка он спрашивает снова через неделю.
  - В строке трата, привязанная к регулярной трате или покупке, называется тем, что она оплатила («Коммуналка Московский 18к5»), а получатель из банка (prostoplatSBP) стоит в подписи. Где трата считается, показывает точка перед суммой: жёлтая — в неделе, фиолетовая — в дополнительных, пустое кольцо — вне бюджета. При наведении на точку видно, что она значит.
  - «Оплата» — платежи, которые трата могла оплатить: регулярные траты со сроком в пределах 10 дней и покупки из плана в пределах двух недель (дополнительные — в пределах месяца). Первыми идут регулярные траты, которым осталось заплатить столько же, сколько стоит трата, с разницей до 10%: счёт оплачивают его суммой. За ними — весь план недели траты, сколько бы в нём ни было покупок, а если кнопок меньше четырёх, их добирают остальные. Внутри каждой группы ближе по оставшейся сумме — раньше, так что телефон за 1 500 ₽ со сроком 2 октября не вытесняет план недели у траты в 1 797 ₽. Уже закрытые другими тратами и купленные не предлагаются. Желание с выбранным планом предлагается, если его покупают в пределах двух недель от траты или в том же месяце. Остальные регулярные траты, покупки и желания — в списке «Другой платёж».
  - «Категория» — все категории, кроме скрытых, первыми те, куда трат больше всего за последние три месяца. Выбор в приложении главнее категории из ZenMoney, так что неправильно определённую ZenMoney категорию можно поменять; кнопка с пометкой «из ZenMoney» возвращает её категорию. Пока трата привязана к регулярной трате, категорию не выбрать.
  - «Тип траты» — переключатель «Необязательная»: уже сделанная трата, без которой можно было обойтись. Его включают и выключают тем же нажатием; трата обязательная, пока его не включили. Тип покупки на трату не переходит: «Гибкая» значит, что покупку можно перенести или отменить, а не что она была не нужна. У необязательной траты сумма в строке оранжевая (при наведении — «Необязательная»), а точка перед ней по-прежнему говорит, где трата считается. У не учитываемой траты и у дохода переключателя нет: на них нечего сэкономить.
  - «Бюджет» — неделя, дополнительные, вне бюджета или «Не учитывать». Не учитываемая трата, например снятые наличные, которые просто лежат, пропадает из трат недели, с `/uncategorized`, из подсказок и всех сумм; в операциях она остаётся бледной строкой «не учитывается», чтобы её можно было найти и вернуть. Платёж считается там же, где то, что он оплатил: регулярная трата — вне бюджета, покупка — в неделе или дополнительных, как она сама, а покупка желания — вне бюджета, потому что её деньги план желания уже отложил в неделях и дополнительных; привязка сбрасывает ручной перенос.
  - «Описание» — что ты сам напишешь о трате, например «Подарок маме», до 200 символов в одну строку; «Сохранить» с пустым полем его убирает. Описание стоит в строке траты: в операциях — перед комментарием банка, в неделе и на `/uncategorized` — после категории, и поиск в операциях его находит.
  - Внизу раскрытой траты — «Название и значок магазина →»: ссылка открывает форму её магазина на вкладке «Магазины» настроек, а «Сохранить» и «Отмена» возвращают к той же раскрытой трате. Человек в переводе («Кирилл А.») магазином не считается, у его трат ссылки нет. Подсказки, подкатегории и разбор месяца по-прежнему идут по получателю из ZenMoney, а не по твоему названию.
  - Всё хранится в `data/settings.db`, в ZenMoney не пишется. Трата, привязанная к покупке, сохраняет свою категорию, а без неё видна в операциях под «Покупками из плана»; привязанная к регулярной трате — под «Регулярными тратами».
- Разметка дохода — в операциях, так же на месте и одним нажатием, только платить доходу нечего. Сверху «О доходе»: когда, сумма, счёт и что сказал банк. «Категория» — категории доходов, а не трат: доходные категории ZenMoney (Salary, Correction) и свои, которые добавляют в настройках; первыми те, куда доходов больше всего за три месяца. Если ZenMoney дал доходу категорию трат, например возврату с заправки, она тоже стоит в списке с пометкой «из ZenMoney». Подсказка — категория, которую этот плательщик получает чаще всего, а у дохода без плательщика, как проценты на остаток или кэшбэк, вместо плательщика берётся комментарий банка: отнесёшь одни «Проценты на остаток» к «Процентам» — остальные предложат то же. «Учёт» — «В доходах» или «Не учитывать»: не учитываемый доход, например возмещение командировочных или вернувшийся долг, пропадает из «получено», итога дня и «Накоплений», а в операциях остаётся бледной строкой «не учитывается». «Описание» — как у траты. Доходы в «Ждут разбора» не попадают.
- `/income` — доходы. У каждого своя модель: «Фиксированная сумма» приходит в заданное число, «Зарплата с авансом» — аванс в день аванса и остаток в день зарплаты следующего месяца. Аванс = зарплата × рабочие дни с 1 по 15 число / рабочие дни месяца. Если день выплаты зарплаты выпадает на выходной, она приходит в предыдущий рабочий день (ст. 136 ТК). Ниже списка ближайшие поступления с расчётом каждой суммы.
- `/regular` — регулярные траты: название, сумма и число месяца. Список идёт в порядке месяца: сверху приглушённые платежи, которые уже позади, потом черта «Сегодня» и предстоящие, ближайший первым. Траты, у которых в этом месяце платежа нет, потому что они начинаются позже, стоят отдельно, в группе «Начнутся позже». Платёж позади, если его число уже прошло или привязанные к нему траты (на `/uncategorized`) покрыли сумму, даже раньше срока; тогда у него галочка и «оплачено 5 октября». Строка открывается для правки по клику, внизу форма для новой. Сбоку сколько осталось заплатить в этом месяце и из какой суммы (траты, которые начинаются со следующего месяца, не считаются), полоса оплаченного, прошедшего и предстоящего и календарь платежей. Платежи недели видны в её плане на обзоре; если числа нет в месяце (30 февраля), платёж приходится на последний день.
- `/settings` — настройки. Сначала «Бюджет»: в «Неделя начинается» одним нажатием выбирают день (Пн … Вс), с которого начинается неделя и обновляются 45 000 ₽. Покупки и суммы недель при этом переезжают в недели, на которые приходится больше их дней: стрижка, запланированная на неделю 12–18 октября, при неделе с пятницы окажется в неделе 9–15 октября, а при возврате к понедельнику вернётся. Сумму отдельной недели меняют на странице недели. «Круглые цифры» в «Главной приложения» одним нажатием включают и выключают суммы до сотен на главной приложения (как они складываются — в «Приложении для iPhone»); страницы сайта всегда точные. «Переводы себе» — твоё имя, как его пишет банк в переводах на твои счета в других банках (например, «Кирилл А.»): разбор месяца откладывает такие переводы отдельно от переводов людям; пустое поле его забывает. В «Claude» — «Токен Claude» из `claude setup-token`: с ним сервер сам разбирает месяц, когда на разборе нажимают «Попросить Claude» или «Пересмотреть». На странице видны только последние четыре символа токена, а поле всегда пустое: новый токен заменяет старый, «Удалить» его забывает. Хранится он в `settings.db`. Потом «Категории расходов» в том порядке, в каком они предлагаются, с числом трат за три месяца, и так же «Категории доходов» с числом доходов. Категорию из ZenMoney можно переименовать (Groceries → Продукты, новое название видно везде в приложении; пустое поле возвращает название из ZenMoney) или скрыть, чтобы она не предлагалась. В форме категории выбирают иконку из шестидесяти («По названию» оставляет ту, что подходит к названию: у «Продуктов» — тележка), цвет — кружком из пятнадцати, «A» («Как у категории») или любым на круге цветов, — и «Фото вместо иконки» с компьютера или телефона. Страница сразу показывает выбранные цвет и фото на значке формы, уменьшает фото до квадрата 240 точек и отправляет вместе с формой: снимок обрезается по квадрату, а картинка с прозрачным фоном (иконка, логотип) вписывается целиком с полями, и сквозь прозрачное видно цвет категории. «Убрать фото» возвращает иконку. Иконка, цвет и фото видны везде, где видна категория: в строках трат и операций, в «Расходах по категориям», в разметке; без выбора у категорий свои иконка и цвет по названию. В каждый список можно добавить свою категорию; удалённая своя категория возвращает свои траты или доходы без категории. Категория ZenMoney, которая и доходная, и расходная (Correction), стоит в обоих списках, а скрытая — один раз в «Скрытых». ZenMoney при этом не меняется. Всё это — вкладка «Основные»; рядом вкладка «Магазины».
- `/settings/shops` — вкладка «Магазины» настроек: магазины, в которых были операции за три месяца, сначала самые частые, со значком, названием и тем, как ещё их называет банк («Lenta-0089, Lenta-0178, LENTA 089 и ещё 10 названий · 13 операций за три месяца»). Поиск «Найти магазин» ищет среди всех магазинов за всё время — по названию, по названию в банке и по-русски для латиницы («аптечный» найдёт APTECHNYY PUNKT). Строка раскрывается на месте (`?edit=<магазин>`). Сверху «Название и значок»: «Название», «Сайт для значка» и «Фото вместо значка» для всех операций этого магазина, и новых тоже. Пустое поле оставляет название и сайт известной сети или название банка. Свой сайт и фото стоят выше значка, который пришёл с приложением, а «Сбросить» его возвращает. Сайт можно вставить адресом из браузера: `https://www.coffeeman.ru/menu` станет coffeeman.ru, и значок появится сразу после «Сохранить». Фото — снимок вывески или логотип — ложится вместо значка на белое. «Убрать фото» возвращает значок, «Сбросить» — всё, что было до тебя. Ниже «Из чего состоит» — все названия, под которыми банк пишет этот магазин, с числом операций и датой последней («SAMOKAT — 39 операций, последняя 12 октября»). Дальше «Объединить с»: магазины, похожие на этот, — с тем же названием или с ключом, который начинается или кончается ключом этого (OKTYABRSKIJ_22V и KEM OKTYABRSKIJ 22V), — стоят кнопками со звёздочкой; две разные сети, вроде «Яндекса» и «Яндекс Еды», похожими не считаются, а любой другой находится в «Другом магазине» поиском «Найти магазин, чтобы объединить» — по названию, по названию в банке и по-русски для латиницы («московский» найдёт Kemerovo Moskovskiy 11). Найденные, сначала частые, появляются по мере ввода, без Enter, и встают такими же кнопками — до двенадцати, о прочих сказано «И ещё 5 — уточните поиск.»; подсказанные выше среди них не повторяются. Объединение и отделение идут без перезагрузки страницы: она обновляется на месте, поиск остаётся там же на экране и с тем же запросом, так что найденные объединяются один за другим (набрал «kokb» — и по очереди нажал на все KOKB). Объединённый уходит в этот магазин со всеми своими операциями и с тем, что было объединено с ним; если у этого магазина своего названия или сайта нет, он берёт их у объединённого, а без них — самое частое название банка, чтобы все операции назывались одинаково. Объединённые магазины видны в «Объединено»; нажатие на такой магазин его отделяет, и он возвращается со своими названием и значком. После объединения и отделения магазин остаётся раскрытым.
- `/storyboard` — все виджеты интерфейса в типовых состояниях, цвета и иконки.
- При запуске, раз в 10 минут (`SYNC_MINUTES`, 0 выключает) и по кнопке «Обновить» сервер синхронизируется с ZenMoney, если в `.env` есть токен.
- `/api/…` — те же экраны в JSON для приложения на iPhone: `/api/week?week=…`, `/api/month?month=…`, `/api/spending/<id>` (трата или доход), `/api/operations`, `/api/uncategorized`, `/api/regular`, `/api/income`, `/api/categories`, `/api/budget-settings` (день начала недели), `/api/wish?id=…&ways=…` (страница желания: способы, план и сколько собрано; без `ways` — выбранный план), `/api/wishes` (все желания: карточки с выбранными планами и ситуацией каждого — `situation`: calm, risk, problem или action, — и деньги планов по месяцам), `/api/widget` (для виджетов: неделя с днями, потрачено сегодня, ждут разбора, накопления по месяцам, ближайший платёж), `/api/session`. Неделя несёт и главную приложения (`home`: свободно с тем, насколько полна неделя, зарезервировано по типам, потрачено сегодня, сколько ждут разбора, когда сервер синхронизировался), месяц — куда уходит доход (`flow`), операции — плашки трат и сколько ждут разбора. Суммы, подписи и статусы считает сервер, так что приложение говорит теми же словами, что и страницы. Изменения приходят теми же формами на те же пути с приставкой `/api` (`POST /api/purchases`, `/api/spending/<id>/tag-…`, `/api/wishes/<id>/due`, `/api/wishes/<id>/ways`, `/api/wishes/<id>/ways/delete`, `/api/sync`), а в ответ приходит `{"status":"saved"}`, 404 с `error` или 422 с `errors` по полям.
- Если в `.env` задан `ACCESS_TOKEN`, без него сервер ничего не показывает: приложение присылает токен в `Authorization: Bearer …`, браузер один раз вводит его на `/login` и получает cookie на год. Без `ACCESS_TOKEN` сервер открыт, как на Mac. `HOST=127.0.0.1` оставляет его доступным только с самого компьютера, за прокси.
- Пока локальной базы нет, показываются демо-данные; `?demo` включает их и при наличии базы. План недель, желания, разметку трат и доходов, категории, доходы и регулярные траты демо-режим не подменяет.

Экраны собираются только из виджетов `src/web/widgets`, без своей разметки и стилей, поэтому одинаковые вещи везде выглядят одинаково. Стили и цветовые токены лежат в `src/web/styles.css`, акцентные цвета виджеты получают через тон (`tone: 'violet'`). У каждого виджета есть истории в `src/web/stories.ts`: их показывает `/storyboard`, а тест падает, если у нового виджета историй нет.

## Приложение для iPhone

`ios/` — приложение на SwiftUI для iOS 17 и новее. Оно показывает то же, что веб-интерфейс, и читает всё с сервера через `/api`. Своих данных и своей логики у приложения нет, поэтому разметка в приложении сразу видна в вебе, и наоборот.

Приложение выглядит по референсу, который выбрал пользователь: тёплая белая страница с мягким сиреневым светом, крупные суммы жирным шрифтом с ₽ того же веса, строки прямо на странице под тихими заголовками дней, у каждой строки точка цвета категории в ореоле. Переключатели — светлая дорожка, выбранное на белом; формы пишут название и сумму крупно, а главную кнопку — фиолетовой внизу. Рубль в приложении пишется ₽, хотя в ZenMoney и в вебе он «руб.». Счёт, с которого списано, и время в строках не показываются, они есть в листе траты. Строка слегка проседает под пальцем, выбранное переезжает плавно со щелчком, суммы меняются анимацией. Внизу белая панель со скруглёнными верхними углами по картинке пользователя: слева «Главная» и «Операции», справа «План» и «Ещё», выбранная вкладка фиолетовая, а между ними над краем панели приподнята круглая фиолетовая «+» в сиреневом ореоле. «+» открывает меню «В план недели», «В дополнительные» и «Желание» — те же формы, что на странице плана, покупка идёт в текущую неделю. Вкладки помнят, где остановились, но нажатие на уже открытую «Главную» и виджет «Неделя» возвращают главную страницу: текущая неделя, «Неделя», без открытых поверх страниц вроде трат недели.

- «Главная» — «Неделя» и «Месяц».
  - Неделя помещается на экран. Сверху дни недели с того дня, с которого неделя начинается в настройках (Пн Вт …): сегодня на фиолетовом круге, точка под днём темнее, если в нём есть траты. Посередине большой круг: на сиреневой линзе «Свободно» и плашка «из 45 000 ✎», справа «Зарезервировано» — что держит план из денег недели, и под ним обязательное и гибкое. По дну линзы медленно качается волна, она поднимается при открытии и тем выше, чем больше недели осталось: фиолетовая, пока денег достаточно, бледная, когда осталось меньше дневной доли недели (45 000 ₽ / 7), никакой при нуле и красная при перерасходе — тогда вместо «Свободно» красная сумма перерасхода и плашка «сверх 45 000 ✎», а волна тем выше, чем дальше неделя ушла за свою сумму. «Свободно» поднимается над высокой волной. Состояние и долю считает сервер (`home.free.state`, `home.free.share`). Под кругом две карточки по картинке пользователя. Слева «Сегодня потрачено» (только то, что идёт в неделю) и под суммой время, когда сервер последний раз забирал данные из ZenMoney («↻ 12:43», нажатие обновляет). Справа на сиреневом «Разобрать операции» и «3 новые» — сколько трат месяца ждут разбора, с красной точкой на иконке; карточка открывает «Ждут разбора» в операциях. Когда разобрано всё, её место занимает «Доп. бюджет» — сколько свободно в дополнительных месяца, к которому относится неделя, «из 100 000 ₽», а при перерасходе красная сумма «сверх 100 000 ₽»; карточка открывает «Месяц» этой недели сразу на «Дополнительных». У прошлой недели вместо «Свободно» — «Итог недели» и «Потрачено за неделю», у будущей — «Будет свободно». Иконка календаря выбирает неделю по любому её дню, со стрелками и «Сейчас»; свайп по кругу листает недели.
  - Плашка открывает «Бюджет недели»: сумму недели и, если она своя, «Вернуть 45 000 ₽»; своя сумма делает плашку фиолетовой.
  - «Зарезервировано» открывает вкладку «План» на той неделе, что показывает главная.
  - День или карточка «Сегодня потрачено» открывают траты недели по дням, с лентой дней, чтобы оставить один день.
  - С «Круглыми цифрами» в настройках главная показывает итоги до сотен: на «Неделе» свободно, зарезервировано с обязательным и гибким, потрачено сегодня или за неделю и доп. бюджет на карточке, на «Месяце» доход и куда он уходит, недели и дополнительные. Части при этом складываются в целое, как точные: свободное, зарезервированное и потраченное — в сумму недели, части дохода — в доход, потраченное, план и свободное дополнительных — в 100 000 ₽. Каждая часть сначала округляется вниз, а сотни, которых не хватает до целого, получают части, потерявшие больше других: 4 111 потрачено, 46 700 зарезервировано и 5 811 перерасхода становятся 4 100, 46 700 и 5 800, а не 44 900 в сумме. Волна стоит по круглому свободному, заголовок вкладки «План» тоже круглый, а траты и покупки в строках и сумма недели на плашке остаются точными; виджеты и остальные экраны — тоже.
  - Месяц: доход и куда он уходит — сиреневые ленты от дохода к обязательным расходам (регулярные траты месяца), недельным бюджетам (суммы недель месяца), доп. бюджету (100 000 ₽), «На желания» — тому, что планы желаний берут из накоплений месяца, если берут, — и «В накопления» — тому, что остаётся; у каждой части сумма и доля дохода. Доход — сколько доходы со страницы «Доходы» приносят в месяц. Если остатка нет, вместо накоплений красное «Не хватает». Ниже недели месяца, каждая открывает свою неделю, и дополнительные: сколько осталось, полоса, покупки и перенесённые туда траты.
- Траты называются магазином, как в вебе («Лента», а не Lenta-0089), а у магазина со значком вместо точки в строке стоит его значок на белом круге.
- Трата открывается листом: посередине значок магазина, а без него иконка того, на что трата пошла, сумма с копейками, магазин с карандашом, «7 октября, 13:02 · Основной», что ещё сказал банк («в банке — Lenta 089») и подсказка («Похоже на «Продукты»»). Карандаш закрывает лист траты и открывает «Ещё → Магазины» с листом этого магазина. У траты, привязанной к платежу, лист называется платежом, а магазин с карандашом стоит строкой под ним. Под ними карточка того, на что трата пошла: категория или платёж, к которому она привязана, на своём цвете; крестик отменяет выбор. Остальные категории и платежи спрятаны: нажатие на карточку раскрывает «Категория / Платёж» — категории плитками с иконками, платежи карточками регулярных трат и покупок, остальные строкой «Другой платёж», подсказка отмечена звёздочкой; плитки появляются одна за другой сверху вниз. Выбор отмечается галочкой и сворачивает всё обратно в карточку. У траты без категории и платежа всё раскрыто сразу. Под карточкой карточка «Необязательная» с выключателем, оранжевым, когда он включён. Ниже поле «Описание»: оно растёт до четырёх строк и сохраняется, когда из него уходят, нажимают «Готово» на клавиатуре или закрывают лист. Внизу «Где считается» — так же одна крупная карточка того, где трата считается сейчас, с тем, что это значит; нажатие раскрывает вокруг неё остальные из «Неделя», «Дополнительные», «Вне бюджета» и «Не учитывать», а выбор сворачивает их обратно. Выбор делается одним касанием и виден сразу, не дожидаясь сервера. Открытая из «Ждут разбора», трата показывает «1 из 4», стрелки и «Дальше» к следующей.
- «Операции» — месяц выбирается плашкой, «По категориям» открывает расходы по категориям, а с чипом «Доходы» — доходы по категориям (категория фильтрует список), лупа ищет. Под ними потрачено (и под ним оранжевое «8 000 ₽ необязательные», если такие траты есть) и получено, чипы «Все», «Ждут разбора», «Расходы», «Доходы», «Переводы» и «Необязательные» с числами; с чипом «Необязательные» сверху одна оранжевая сумма — сколько они стоили. У дня в строке его итог; у необязательной траты сумма оранжевая — так же в тратах недели и дополнительных месяца; у траты, которая не обычная для недели, плашка: «Ждёт разбора», «Регулярный», «Дополнительные», «Вне бюджета» или «Не учитывается»; у не учитываемого дохода — «Не учитывается». Доход открывается тем же листом, что и трата, только без «Платежа»: карточка категории раскрывает категории доходов плитками, а в «Где считается» — «В доходах» или «Не учитывать». «Ждут разбора» показывает траты месяца без категории — сколько их и на какую сумму; подсказку принимают кнопкой «Принять» в строке, а ниже «Разобрано». Число ждущих разбора видно на вкладке.
- «План» — план недели: сумма зарезервированного, полоса обязательного и гибкого с долями, «Планируемые траты» из денег недели, «Из дополнительных», «Регулярные платежи» недели и «Хочу купить». У обязательной покупки заполненная точка, у гибкой — кольцо, у купленной и оплаченной — галочка; «+» добавляет покупку в план недели или в дополнительные. Покупку завершают из меню долгого нажатия или в её форме, желание без плана ставят в неделю кнопкой «Запланировать» в строке. Стрелки листают недели вперёд и назад, «Сейчас» возвращает текущую.
  - Звёздочки в заголовке открывают «Желания» — все желания в одном месте, с переключателем «Карточки / Месяцы» (приложение помнит, что выбрано); «+» добавляет новое. «Карточки» — карточка на желание: название, «к 30 ноября · купить 28 ноября – 4 декабря» и сумма, под ними полоса собранного в цветах способов и способы выбранного плана с тем, сколько каждый даёт: «Отложить в ноябре» с «останется 1 400 ₽» — 25 000 ₽, «Ужать недели» с «40 000 вместо 45 000 · 7 недель» — 35 000 ₽; красное «Не хватает 57 000 ₽», если план не собирает сумму, оранжевое «купить 2–8 ноября · позже срока», если покупка выходит позже срока, и кнопки «Изменить» (страница желания) и «Отменить план» (с вопросом). У желания без плана — «Не разложено» и «Разложить», у купленного — «Куплено»; купленные идут последними. «Месяцы» — сначала желания строками со сроком и планом или «не разложено» (долгое нажатие — «Отменить план» и «Удалить»), под ними месяцы с тем, сколько планы желаний берут в каждом, — «Ноябрь 45 000 ₽» — и строками «Резина мне · 7–13 ноября · 40 000 вместо 45 000» или «Дополнительные ноября · отложить». Неделя идёт в тот месяц, к которому её относит план (31 октября – 6 ноября — к ноябрю), дополнительные и накопления — в свой месяц, перенесённая покупка — в месяц недели, откуда её перенесли. Строки открывают желание.
  - Желание открывается своей страницей, она же открывается со строк «Желание» в плане. Сверху название, сумма и «Нужно» с датой (без даты — месяц вперёд, бледно); «Изменить» открывает форму названия и суммы. «Как собрать» — способы карточками: «Отложить в октябре» и «Дополнительные ноября» — свободное в дополнительных каждого месяца до срока, «Подвинуть гибкие» — гибкие покупки из дополнительных до срока переезжают на месяц позже, «Ужать недели» — по столько-то с каждой недели до срока, «Из накоплений» — из накоплений месяца покупки, «Подождать» — дополнительные первого месяца после срока со свободным, покупка тогда переезжает на его первую неделю (оранжевым «позже срока»). Касание карточки включает способ или выключает; у включённого ползунок с шагом 1 000 ₽ — сколько он даёт, у недель — сколько с недели. Сумма, поставленная ползунком, не меняется, остальные способы делят то, что осталось, и первым берёт включённый последним — у такой карточки «остальное». «Как получится» — шаги по датам с чертой «Сейчас» и «Купить»; внизу закреплено «Собрано 60 000 из 60 000 ₽» с полосой в цветах способов, «Не хватает», если не хватает, и «Выбрать» или «Выбрано» с «Отменить». Выбранный план держит деньги в неделях и дополнительных покупками желания, переносит гибкие покупки и уменьшает накопления месяца; новый выбор сохраняет то, что старый уже отложил в прошедших неделях и месяцах.
- «Ещё» — переключатель «Регулярные / Доходы / Категории / Магазины»: регулярные траты в порядке месяца с чертой «Сегодня» и полосой оплаченного, доходы с ближайшими поступлениями, категории — расходов, под ними «Доходы» со своей кнопкой «Добавить категорию дохода», скрытые вместе внизу, — и магазины за три месяца, сначала самые частые, с числом магазинов сверху, полем «Найти магазин» (ищет по всем, по кнопке поиска на клавиатуре) и строками со значком, названием и другими названиями банка. Магазин открывает лист «Магазин»: значок, «Название», «Сайт для значка», «Фото вместо значка» и «Из чего состоит» — названия банка с числом операций; «Сбросить» вверху возвращает всё как было. Объединяют магазины в вебе. Формы те же, что в вебе. Лист категории сверху показывает, как она будет выглядеть, ниже название, сетка иконок («Aa» — по названию), кружки цветов с «A» и кругом своего цвета и «Фото вместо иконки»: фото из галереи телефон сам уменьшает так же, как страница, «Убрать фото» возвращает иконку. Фото категории видно в её строке, на плитках и карточке разметки траты и в «Расходах по категориям»; точки в строках трат берут цвет категории. Шестерёнка открывает «Настройки»: «Неделя начинается» (Пн … Вс одним касанием, сразу сохраняется), сколько на неделю обычно, выключатель «Круглые цифры» (тоже сразу), сервер — «Рабочий / Тестовый», адрес, «Обновить из ZenMoney», «Сменить сервер» и выход. Пилюля без сервера открывает только сервер.
- Потяните список вниз, чтобы сервер забрал новое из ZenMoney. То же происходит при каждом открытии приложения.
- Поясняющих фраз, как в вебе, в приложении нет: цифры говорят сами за себя.
- Без сервера приложение показывает то, что сохранило. Последний ответ сервера по каждому открытому экрану хранится на телефоне, и экран открывается сразу с ним, пока сервер отвечает. Если сервер не ответил за 15 секунд или прокси перед ним вернул 502–504, сохранённое остаётся на экране, а над листом появляется тёмная пилюля с перечёркнутым Wi‑Fi и временем сохранения («22:43» сегодня, «6 окт., 22:43» раньше). Нажатие на пилюлю открывает сервер. Экран, которого на телефоне ещё нет, показывает «Не удалось загрузить» с кнопками «Повторить» и «Сервер». Изменения без сервера не сохраняются, приложение сообщает об этом.
- Над сервером переключатель «Рабочий / Тестовый»: рабочий — сервер в интернете, тестовый — сервер на Mac по http, сначала `http://MacBook-Pro-kir.local:4318` без токена. Приложение помнит адрес и токен каждого, сервер, на который входили по https, становится рабочим, по http — тестовым, так что переключение — одно касание; если рабочий на этом телефоне ещё не подключали, касание открывает форму с `https://budget.gang.su`, где остаётся вписать токен. Выбранный сервер сначала проверяется; если он не отвечает, приложение остаётся на прежнем и говорит, что адрес не отвечает. Виджеты переходят вслед за приложением. Сохранённое на телефоне общее, поэтому после переключения экран сначала может показать прежний сервер, пока новый не ответит.
- «Сменить сервер» принимает адрес и токен и сначала проверяет новый сервер: если адрес неверный, приложение остаётся на прежнем сервере с тем, что сохранило. «Выйти» удаляет сохранённое на телефоне. Копия, которая на 60 дней старше самой свежей, удаляется при запуске.

Виджеты нарисованы по референсу пользователя в том же сиреневом стиле, что и приложение: белые карточки, крупные суммы, у недели — сиреневый свет в углу. Их пять, каждый добавляется отдельно: долгое нажатие на экран «Домой» → «Изменить» → «Добавить виджет» → «Бюджет».

- «Неделя» — «Неделя», сколько свободно крупно, «свободно до конца недели» (или красная сумма и «потрачено сверх недели»), а под ними дни недели с того дня, с которого неделя начинается: сегодня на фиолетовом круге, точка темнее, если в дне есть траты. Средний и маленький; открывает неделю.
- «Сегодня» — «Сегодня потрачено» (только то, что идёт в неделю), «Обновлено 18:42» и кольцо с числом трат этого месяца, которые ждут разбора. Кольцо — доля трат месяца, у которых уже есть категория: когда разобрано всё, оно замкнуто, а внутри галочка и «Всё разобрано». Нажатие на «Обновлено» просит сервер забрать новое из ZenMoney и перечитывает все виджеты, на кольцо — открывает «Ждут разбора». Средний; в маленьком кольцо поменьше, под суммой.
- «Накопления» — доходы месяца минус его расходы, как их считают «Операции» (без переводов между своими счетами и без того, что «Не учитывается»), и сравнение с прошлым месяцем: «на 27% больше», а если хоть один из двух месяцев ушёл в минус — в рублях. Столбики — последние 10 месяцев, текущий самый тёмный; месяц в минусе — бледно-красный столбик вниз. Маленький; открывает операции.
- «Ближайший платёж» — следующий неоплаченный регулярный платёж: название, сколько осталось заплатить, дата и «через 12 дней». Маленький; открывает «Ещё» с регулярными.
- «Доп. бюджет» — как карточка на главной: кошелёк на плитке, сколько свободно в дополнительных этого месяца и «из 100 000 ₽» (при перерасходе красная сумма и «сверх 100 000 ₽»), под ними полоса: потраченное фиолетовым, то, что держит план, светлее, свободное пустым. В среднем под полосой ещё «потрачено 17 616» и «в плане 19 506». Маленький и средний; открывает «Месяц» на «Дополнительных».

На экране блокировки «Неделя», «Сегодня», «Ближайший платёж» и «Доп. бюджет» — карточки с иконкой на плитке: свободная сумма недели; «Все операции разобраны» с «Отличная работа!» или «4 траты ждут разбора» с суммой; платёж с суммой и сроком; свободное в дополнительных с «Доп. бюджет · из 100 000 ₽». «Неделя» есть и строкой над часами. Виджеты сами читают сервер раз в 15 минут (точное время решает iOS, бывает и реже) и сразу после любого изменения в приложении. Адрес сервера и токен они берут из общей с приложением связки ключей, поэтому входить в них отдельно не нужно. Если сервер недоступен, виджет показывает последнее, что прочитал, бледнее.

Установка на iPhone. Нужны Xcode (из App Store) и Apple ID, добавленный в Xcode → Settings → Accounts; в проекте уже выбрана личная команда этого Apple ID (`DEVELOPMENT_TEAM`), для другого Apple ID её меняют в Signing & Capabilities обеих целей, Budget и BudgetWidgetExtension.

1. Подключите iPhone кабелем, нажмите на нём «Доверять этому компьютеру» и включите режим разработчика: Настройки → Конфиденциальность и безопасность → Режим разработчика.
2. `make ios-install` собирает приложение с виджетом, ставит на телефон и открывает его, если телефон разблокирован.
3. Первый раз на iPhone: Настройки → Основные → VPN и управление устройством → доверять своему Apple ID.
4. В приложении введите адрес сервера и токен доступа. Для сервера на этом Mac (`make web`) — `http://MacBook-Pro-kir.local:4317` без токена: телефон должен быть в той же сети, Mac — не спать. Для сервера в интернете — его адрес и токен (см. «Сервер в интернете»).

С бесплатным Apple ID приложение открывается 7 дней, потом нужен снова `make ios-install`: данные и вход сохраняются. С платной подпиской Apple Developer — год.

`ios/screens.sh http://localhost:4318 <папка>` проходит по экранам приложения в симуляторе iOS и сохраняет скриншот каждого (UI-тест `ios/BudgetUITests`). Тест только открывает и закрывает экраны, поэтому его можно запускать на настоящих данных. `testOffline` открывает приложение второй раз с несуществующим сервером, проверяет, что сохранённое видно, и возвращается на рабочий сервер через «Сменить сервер». Тест разметки (`testMarking`) выбирает и отменяет категорию, платёж и бюджет, поэтому запускается только с `TEST_RUNNER_MARKING=1` и против сервера с копией баз. Так же, с `TEST_RUNNER_WISHES=1`, запускается `testWishPlan`: он открывает первое желание, включает недели и дополнительные, выбирает план и отменяет его. Адрес сервера приложение берёт и из аргумента запуска `-server http://…`.

`make ios-check` проверяет приложение без iPhone. Модели приложения читают все экраны API, собранные из демо-данных (`ios/fixtures.ts` → `ios/FixtureCheck`). Код собирается под симулятор iOS, а если Xcode не установлен — под macOS через `ios/Package.swift`. Его запускает и `make check`, так что изменение JSON, которое приложение не прочтёт, не пройдёт проверку.

## Сервер в интернете

Чтобы приложение работало всегда, а не только когда Mac включён и рядом, сервер живёт на VPS рядом с SecondBrain: <https://budget.gang.su>. Его разворачивает репо `infra17` (`~/orca/projects/infra17`, ansible) — общий для всех сервисов на этой машине, бюджет в нём — запись `budget` в `group_vars/all/services.yml`. Команды запускаются из `infra17`:

```sh
make deploy S=budget                                   # всё: пользователь, код с GitHub, Node.js, .env, служба, HTTPS
make app S=budget                                      # только новый код из main на GitHub и рестарт
make env S=budget K=ZENMONEY_TOKEN                     # задать ключ в .env сервера (значение спросит)
make data S=budget FROM=~/orca/projects/budget17/data  # базы с этого Mac поверх серверных
```

- Код сервер берёт сам из `git@github.com:paglliac/budget17.git` (ветка `main`) своим deploy key только на чтение, так что новый код сначала уходит на GitHub (`git push origin main`), а потом на сервер (`make app S=budget`).
- Служба `budget` работает под пользователем `budget`: код в `/srv/budget/app`, базы в `/srv/budget/data` (в чекауте на них смотрит `data`), токены в `/srv/budget/.env`. Node.js 24 с nodejs.org лежит в `/opt/node`. Сервер слушает только `127.0.0.1:4317`, снаружи к нему идут через Caddy по HTTPS, часовой пояс — Europe/Moscow.
- `ACCESS_TOKEN` создаётся на сервере при первом запуске. `ZENMONEY_TOKEN` берётся из `.env` этого Mac, если в `inventory.local.yml` у `infra17` указан `budget_env_file`, иначе задаётся через `make env`. Дальше `.env` сервера не меняется. Токен для приложения и браузера — `ACCESS_TOKEN` в этом файле.
- `make data` переносит `data/settings.db` и `data/zenmoney.db` с Mac поверх серверных: всё, что вы ввели в веб-интерфейсе на Mac, едет вместе с ними. Приложение на iPhone пишет в базы сервера, поэтому `make data` затирает всё, что размечено на телефоне после прошлого переноса. После переноса пользуйтесь сервером и с Mac (браузер, `/login`), иначе разметка на Mac и на сервере разойдётся.
- Обратно, с сервера на Mac, базы приносит `make pull-data` из этого репо: разработку и проверку в отдельной копии (worktree) можно вести на тех же данных, что видит телефон, с разметкой с телефона. Команда заходит на сервер по ssh (`budget.gang.su` или `VDS=пользователь@хост`), там Node.js снимает каждую базу через `VACUUM INTO` — целиком, даже если служба в этот момент пишет, — и кладёт `settings.db` и `zenmoney.db` в `data/` той копии, откуда её запустили. На сервере ничего не меняется. Сервер этой копии видит новые базы со следующего запроса, перезапускать его не нужно. Если `data` — ссылка на чужую папку, команда откажется, а в основной копии, где лежит введённое на Mac, спросит подтверждение.

## Разбор месяца с Claude

Выводы, подсказки и ответы на разборе месяца пишет Claude по подписке, через `claude` (Claude Code); ключ Claude API не нужен. Запускают его двумя способами.

- Сам сервер, если в настройках задан «Токен Claude» (его выдаёт `claude setup-token`, токен живёт год). По «Попросить Claude» или «Пересмотреть» сервер в фоне, по одному месяцу за раз, вызывает `claude -p` с этим токеном и кладёт ответ в `settings.db`. На машине сервера должен быть установлен `claude`. Если Claude не ответил (нет `claude`, токен не подошёл, ответ не по схеме), карточка разбора пишет почему и снова предлагает кнопку; просьба ждёт, пока её не повторят.
- `make claude-review` — без токена, под тем, кто вошёл в `claude` на этой машине; сервер тогда только отдаёт месяц и принимает ответ.

```sh
make claude-review MONTH=2026-09                               # разобрать сентябрь на сервере localhost:4317
make claude-review SERVER=http://localhost:4318                # разобрать то, что просили кнопкой на странице
make claude-review SERVER=http://localhost:4318 WATCH=1        # ждать просьб и разбирать их по одной
```

- Команда берёт месяц с `GET /api/review/claude/input?month=2026-09` — недели, итоги, категории против трёх прошлых месяцев, траты недель с разметкой и описаниями, получателей с тем, как размечались их траты раньше, и, если Claude месяц уже разбирал, что стало с каждой его подсказкой. Затем запускает `claude -p` без инструментов с промптом `src/claude/review.md` и схемой `src/claude/review.schema.json` и отправляет ответ на `POST /api/review/claude/answer?month=2026-09` (JSON). Разбор сентября — 232 траты — идёт несколько минут.
- Сервер проверяет ответ по схеме и выкидывает то, что называет чужие траты или несуществующие категории (команда пишет, что пропущено), и хранит его в `settings.db` вместо прежнего за этот месяц.
- Без токена кнопки «Попросить Claude» и «Пересмотреть» только ставят просьбу; список просьб — `GET /api/review/claude/requests`. На сервере с `ACCESS_TOKEN` команда шлёт его из окружения.

## Устройство

- `scripts/pull-data.sh` — `make pull-data`: базы сервера в `data/` этой копии по ssh (см. «Сервер в интернете»).
- `src/zenmoney/types.ts` — сущности API: счета, операции, категории, валюты и т.д.
- `src/zenmoney/client.ts` — клиент для `/v8/diff`, единственного эндпоинта синхронизации.
- `src/store.ts` — локальная копия данных в SQLite.
- `src/sync.ts` — синхронизация: скачивает изменения и сохраняет их в базу.
- `src/balances.ts` — расчёт балансов и конвертация валют (чистые функции).
- `src/week.ts` — бюджет неделями: лимиты и сумма отдельной недели, покупки с типом (обязательная или гибкая) и сколько из плана держат обязательные, недели с выбранного дня и их месяцы, куда переезжает неделя при смене дня (`alignWeek`), сводка недели и дополнительных месяца, подсказка, когда покупать желание.
- `src/wish-plans.ts` — как купить желание к сроку: способы (`waysOf`), план из выбранных способов (`combinedPlan`: заданные вручную суммы, затем остальное, первым — включённый последним), шаги, которые новый план сохраняет (`begunSteps`), и деньги выбранных планов как покупки желаний в неделях и дополнительных (`wishPurchases`, их кладёт в бюджет `plannedPurchases` в `src/web/pages/dashboard.ts`). Страница желания в API и формы `/wishes/:id/due`, `/wishes/:id/ways`, `/wishes/:id/ways/delete` — `src/web/pages/wishes.ts`.
- `src/review.ts` — разбор месяца: чем оказалась каждая трата его недель (обычная, перевод человеку, перевод себе, без категории, дополнительная, регулярная, вне бюджета), итоги и траты с категорией в неделю против трёх прошлых месяцев, регулярные платежи месяца и что их оплатило (`payments`), выводы (`findings`), подсказка, что оплатил перевод себе (`transferHint`), из чего сделаны недели (`weekParts`: категории и группы для проверки, а в них подкатегории, получатели или суммы) и подсказки на правилах (`reviewHints`). Страницы и формы `/review/…` — `src/web/pages/review.ts`.
- `src/claude-review.ts` — разбор месяца от Claude: ответ по схеме и его проверка (`readAnswer`: траты и категории, которых нет, выпадают), что из подсказок, вопросов и разбиений ещё ждёт пользователя (`openWord`: принятое, отклонённое, отвеченное и размеченное по-своему уходит) и месяц в том виде, в каком его получает Claude (`claudeInput`). `src/claude/review.md` — промпт, `src/claude/review.schema.json` — JSON Schema ответа, `src/claude/ask.ts` — вызов `claude -p` по подписке (с токеном из настроек или под вошедшим пользователем), `src/claude/run.ts` — `make claude-review`. `src/schema.ts` — проверка JSON по той части JSON Schema, что нужна ответу.
- `src/payees.ts` — получатели: один магазин при любом номере и алфавите (`shopKey`, `shopName`), магазин без пометки оплаты по QR и СБП (`shopOf`) и человек в переводе по СБП (`isPerson`).
- `src/shops.ts` — магазины: известные сети с русскими названиями и сайтами (`CHAINS`), ключ магазина, общий для всей сети (`shopKeyOf`: SBER*5411*SAMOKAT — samokat), магазин получателя с названием, сайтом и значком от пользователя или от сети, а у объединённого — магазин, в который он ушёл (`shopFinder`, `shopByKey`: значок — фото пользователя, значок его сайта, значок из приложения, значок сайта сети), значки, которые приходят с приложением (`APP_LOGOS`: PNG 240×240 на прозрачном фоне в `src/shop-logos`, имя файла — ключ магазина, версия — по содержимому; откуда взят каждый — в `sources.tsv` там же), и значок сайта от сервиса Яндекса (`fetchSiteIcon`: картинка в один пиксель значит, что значка нет).
- `src/month.ts` — сводка месяца: доходы, расходы по дням и категориям, бюджет.
- `src/categories.ts` — категории для разметки трат и доходов: категории ZenMoney (расходные или доходные) с названиями пользователя, его собственные того же вида, скрытые и порядок по популярности; иконка, цвет и версия фото, которые пользователь дал категории (`CategoryLook`), приходят вместе с ней и в операции; подкатегории и в какую из них попадает трата (`subcategoryOf`): положенная вручную — туда, иначе трата магазина — в подкатегорию своего получателя.
- `src/categorization.ts` — разметка трат и доходов: куда их отнёс пользователь, что подсказать (у операции без получателя — по комментарию банка) и что трата могла оплатить.
- `src/planned.ts` — ближайшие плановые операции.
- `src/income.ts` — доходы и их модели. Модели подключаются через `INCOME_MODELS`: новая модель — это её поля и функция, которая считает выплаты за месяц; параметры хранятся JSON-ом, поэтому миграция не нужна.
- `src/workdays.ts` — производственный календарь РФ: выходные, праздники и их переносы. Переносы по постановлению правительства вносятся в `TRANSFERS` раз в год, когда выходит постановление; сейчас там 2025 и 2026 годы.
- `src/regular.ts` — регулярные траты: даты платежей, какой платёж месяца оплачен, прошёл или впереди, суммы за месяц.
- `src/input.ts` — проверка того, что вводят в формы: названия, суммы, числа месяца, сайт магазина (`parseSite`: адрес из браузера становится lenta.com).
- `src/settings.ts` — то, что настраивается в приложении, в SQLite (`data/settings.db`): регулярные траты, доходы, день начала недели, круглые цифры и имя в переводах себе (таблица `preference`) и суммы отдельных недель (`week_limit`), покупки недель с их типом, желания со сроком и выбранным планом (`wish.due`, `wish.ways`, `wish.buy_week`, шаги — `wish_step`), разметка трат и доходов (категории, привязки к регулярным тратам, покупкам и желаниям — `wish_payment`, перенос в дополнительные, «не учитывать», описания — `spending_description`, необязательные траты — `optional_spending`) и список категорий; иконки, цвета и фото категорий (`category_look`: фото — JPEG или PNG до 400 КБ с версией, которая меняется вместе с ним); своя категория — для расходов или для доходов (`own_category.kind`); токен Claude (`preference.claude_token`); подкатегории (`subcategory`), магазины в них (`payee_subcategory`) и траты, положенные туда вручную (`spending_subcategory`); отклонённые подсказки разбора (`dismissed_hint`); названия, сайты и фото магазинов (`shop_look`, по ключу `shopOf`), объединённые магазины (`shop_merge`: какой магазин в какой ушёл) и значки сайтов, полученные от Яндекса (`site_icon`, с тем, когда их спрашивали); ответ Claude о месяце с тем, какими были траты, когда он пришёл (`claude_review`), просьбы пересмотреть и почему Claude не ответил (`claude_request`) и что сделано с его подсказками (`claude_decision`).
- `src/ledger.ts` — список операций за период (без переводов внутри банка и того, что не учитывается, с категориями из приложения), их фильтры и расходы или доходы по категориям.
- `src/operations.ts`, `src/dates.ts` — вид операции и её сумма, работа с датами.
- `src/format.ts` — вывод в консоль.
- `src/cli.ts` — точка входа.
- `src/web/server.ts` — веб-сервер и JSON API: формы страниц и приложения проходят через одну функцию, вход по `ACCESS_TOKEN`, синхронизация по расписанию, значки сайтов магазинов после синхронизации и при запуске (`refreshLogos`); `src/web/pages` — страницы (разметка траты, общая для обзора, `/uncategorized` и операций, и разметка дохода — в `marking.ts`, вкладка «Магазины» настроек с формой магазина — в `shops.ts`), `src/web/widgets` — виджеты, `src/web/stories.ts` — их истории для сториборда.
- `src/web/api.ts` — экраны для приложения на iPhone: собираются из тех же загрузчиков и фраз страниц, иконки по имени, цвета тоном или `#rrggbb`; рубль в них ₽ (`withRubleSign`). Только здесь считаются главная недели (`weekHome`), куда уходит доход месяца (`monthFlow`) и плашки операций (`operationChip`), и только здесь итоги недели и месяца становятся круглыми (`roundWeek`, `roundExtras`; части целого округляет `roundParts` в `src/web/format.ts` методом наибольшего остатка).
- `src/web/auth.ts` — доступ по `ACCESS_TOKEN`: токен в `Authorization` или cookie со страницы входа (`src/web/pages/login.ts`).
- `ios/Budget` — приложение для iPhone: `Models.swift` — экраны API, `API.swift` и `Session.swift` — запросы, вход, смена сервера и перезагрузка экранов и виджета после любого изменения, `Saved.swift` — последние ответы сервера на телефоне для работы без него, `Design.swift` — вид приложения (`Lilac`: суммы, переключатели, строки с точкой в ореоле, формы, полосы), `Components.swift` — загрузчик экрана (сохранённое сразу, пилюля без сервера) и мелкие части, `BudgetApp.swift` — панель вкладок с «+» и возврат на главную, `HomeView.swift` — неделя с кругом и карточками под ним (`HomeFooter`), план недели (вкладка «План»), траты недели и выбор недели, `BudgetView.swift` — неделя и месяц с потоком дохода (карточка и виджет доп. бюджета открывают месяц на «Дополнительных»), `OperationsView.swift` — операции и «Ждут разбора», `MarkingSheet.swift` — разметка траты и дохода, `ShopsView.swift` — магазины на «Ещё» и лист магазина, куда ведёт карандаш траты (`openShop`), `Sheets.swift` — формы покупки, желания и бюджета недели, `WishView.swift` — страница желания со способами и планом, `WishesView.swift` — «Желания»: все желания карточками и по месяцам, `HomeWave.swift` — волна на круге, `SettingsSheet.swift` — настройки за шестерёнкой: день начала недели и сервер (рабочий и тестовый, переключение — `ServerPanel` в `MoreView.swift`, память о них — `ServerSlot` в `Session.swift`), остальное — экраны «Ещё». `ios/Budget.xcodeproj` подключает папки `Budget`, `Shared`, `BudgetWidget` и `BudgetUITests` целиком, поэтому новые файлы в проект добавлять не нужно.
- `ios/BudgetWidget` — виджеты «Неделя», «Сегодня», «Накопления», «Ближайший платёж» и «Доп. бюджет»: читают `/api/widget` с сервера, адрес и токен которого лежат в общей связке ключей; «Обновлено» — кнопка `SyncIntent`, которая зовёт `/api/sync`. `ios/Shared` — то, что нужно и приложению, и виджетам: связка ключей, деньги, даты, цвета нового стиля (`Lilac.swift`), данные виджетов.
- `src/web/document.ts` — каркас HTML-страницы и небольшие скрипты: первый держит раскрытую или сохранённую запись на том же месте экрана после перезагрузки, второй (`LIVE_SEARCH`) ищет по мере ввода в поле поиска с `live` — спрашивает у сервера ту же страницу с запросом и заменяет найденное под полем, не трогая само поле; третий (`STAY`) отправляет формы с `data-stay` без перезагрузки — ответ сервера заменяет страницу на месте, а часть страницы, где была форма, остаётся там же на экране. Без скриптов поиск ищет по Enter, а формы перезагружают страницу. Иконки сайта сервер отдаёт без токена: `src/web/favicon.png` — шар на прозрачном фоне, он же стоит вверху левой панели, `src/web/apple-touch-icon.png` — шар на фиолетовом квадрате для экрана «Домой»; иконка приложения — `ios/Budget/Assets.xcassets/AppIcon.appiconset`.
- `src/web/html.ts` — сборка HTML: подставленные значения экранируются, разметка виджетов вкладывается как есть.
- `src/web/looks.ts` — как рисуется категория (`categoryLook`): выбранные пользователем иконка и цвет или подходящие к названию (`TITLE_LOOKS` в `src/web/icons.ts`), и фото по адресу `/category-photo/<id>?v=<версия>`; цвета на выбор (`CATEGORY_COLORS`). Сервер отдаёт фото с долгим кэшем: новая версия — новый адрес. Строка операции рисует вместо категории значок своего магазина (`withLogo`, `logoOf`), если он есть: фото пользователя, значок из приложения или значок сайта по адресу `/shop-logo/<магазин>?v=<версия>`, на белом с тонкой обводкой. В приложении фото рисует `ios/Budget/CategoryLook.swift`: грузит его с токеном, держит в памяти и в кэше телефона и уменьшает выбранное в галерее.

## Сделано

1. Клиент API и балансы по счетам.
2. Локальная база (встроенный `node:sqlite`) и инкрементальная синхронизация по `serverTimestamp`, чтобы не скачивать всю историю при каждом запуске.
3. Операции: список за период с фильтрами, расходы по категориям за месяц.
4. Веб-интерфейс: обзор, операции и сториборд виджетов. Это вариант A из прототипа, все четыре варианта лежат в ветке `prototype/ui-variants`.
5. Регулярные траты: страница настройки и календарь платежей; платежи недели видны на обзоре.
6. Доходы с подключаемыми моделями: фиксированная сумма и зарплата с авансом по производственному календарю.
7. Бюджет неделями на обзоре: план недели, желания с подсказкой, когда покупать, разметка трат и месяц по неделям. Это вариант B из прототипа, оба варианта лежат в ветке `prototype/week-budget`.
8. Траты без категории: страница, где их относят к категории или к регулярной трате, с подсказками. Переводы между своими счетами одного банка убраны из операций.
9. Регулярные траты в порядке месяца: прошедшие и оплаченные отделены от предстоящих чертой «Сегодня», траты, которые начнутся позже, — отдельной группой; сбоку сколько осталось заплатить. Это вариант C из прототипа, все три варианта лежат в ветке `prototype/regular-past`.
10. Будущие недели: обзор листается по неделям и месяцам на год вперёд, в будущую неделю можно поставить покупку, например стрижку, и увидеть, сколько останется свободно; покупку можно перенести в другую неделю. Это вариант A из прототипа, все три варианта лежат в ветке `prototype/week-ahead`.
11. Удобная разметка трат: трата раскрывается на месте, без прыжка в начало страницы, и размечается одним нажатием — платёж регулярной траты или покупка из плана, категория (популярные первыми, выбор в приложении главнее ZenMoney) и бюджет, включая «Не учитывать» для снятых наличных; сверху время траты и что о ней знает банк. Так же на обзоре и в операциях. Трата, привязанная к покупке, вычитается из плана, а вместо кнопки «Куплено» у покупки галочка «Завершить» при наведении, которая возвращает остаток. Список категорий меняется на странице настроек. В списках трат привязанная трата называется тем, что она оплатила, а вместо слов «в неделе» и «вне бюджета» стоит точка перед суммой.
12. Неделя наоборот: траты недели по дням занимают основную колонку, а план, «Хочу купить» и сколько можно потратить стоят сбоку, в широкой колонке. Формы новой покупки и желания свёрнуты в строку. Это вариант D из прототипа, все четыре варианта лежат в ветке `prototype/spending-list`.

Приложение для iPhone на SwiftUI: неделя и месяц, разметка трат одним касанием, операции, разбор трат без категории, регулярные траты, доходы и категории, и виджет с остатком недели и тратами без категории. Оно работает с сервером через JSON API, который собирается из тех же функций, что и страницы. Сервер живёт на VPS по адресу budget.gang.su, его разворачивает общий для сервисов репо `infra17` на ansible, с HTTPS и входом по токену доступа.

Что проверить — переводы людям, переводы себе и траты без категории — открывается на своей странице, `/review/check`, по одной группе и размечается на месте. 38. Желание помогает купить себя к сроку: у желания есть дата «Нужно», а его страница в приложении собирает деньги из нескольких способов сразу — дополнительных месяцев до срока, гибких покупок, которые можно подвинуть, недель, накоплений и ожидания следующего месяца, — каждый со своей суммой на ползунке. Выбранный план держит деньги в неделях и дополнительных строками «Желание», а то, что берёт из накоплений, видно в потоке месяца как «На желания». Трату, которая купила желание, привязывают к нему в «Оплате»: она считается вне бюджета, а желание уходит из «Хочу купить». Прототип с тремя видами и вариантом A, который выбрал пользователь, лежит в ветке `prototype/wish-plans`.
39. Траты называются магазином, а не тем, как его пишет банк: Lenta-0089, Lenta-0178 и LENTA 089PQR — это «Лента» со значком Ленты, PYATEROCHKA 9076 — «Пятёрочка», SAMOKAT — «Самокат». 47 сетей называются сами и почти все получают значок своего сайта, остальные магазины называют на вкладке «Магазины» настроек и на «Ещё → Магазины» в приложении, куда ведут ссылка из раскрытой траты и карандаш в листе траты: название, сайт для значка или своё фото — для всех трат магазина сразу. Магазины одной сети — один магазин сами (SAMOKAT и SBER*5411*SAMOKAT — «Самокат»), а остальные, которые банк пишет слишком по-разному (OKTYABRSKIJ_22V и KEM OKTYABRSKIJ 22V), объединяются вручную; там же видно, из чего магазин состоит. Название банка остаётся в сведениях о трате, а подсказки и разбор месяца по-прежнему идут по нему.
40. `make pull-data` приносит базы с сервера в интернете в `data/` копии, откуда её запустили: в отдельном worktree можно разрабатывать и проверять на тех же данных, что видит телефон, с разметкой с телефона.
41. Доп. бюджет на главной и в виджете: под кругом в приложении теперь две карточки по картинке пользователя — «Сегодня потрачено» и «Разобрать операции» с числом новых, а когда всё разобрано, вместо разбора «Доп. бюджет»: сколько свободно в дополнительных месяца из 100 000 ₽; карточка открывает месяц сразу на «Дополнительных». Новый виджет «Доп. бюджет» показывает то же для этого месяца с полосой потраченного и запланированного.
42. У 69 частых магазинов значок теперь приходит с приложением, а не только с сайта: круглый или эмблема на прозрачном фоне, найденные по картинкам в интернете — в Яндекс Картинках, на Яндекс Картах, в 2ГИС, в App Store и RuStore, в Telegram-каналах и на сайтах самих мест. Это сети, где значок сайта был размыт, квадратен или его не было (Бегемаг с бегемотом, Мария-Ра, Ярче, АЗС Форус, Лукойл, МТС), и кемеровские места без сайта сети: Птичий двор, Хлеб из тандыра, Мастерская муки, Coffeeman, HopfenBerg, Take&Wake, пельменная «Ели & Ели», буфет КОКБ и другие. Пять картинок, которые пользователь сам поставил на Mac (Мария-Ра, Spar, Хлеб из тандыра, Forshtadt, автобус), тоже пришли с приложением, так что они видны и на телефоне.
43. Магазин, который нужно объединить с открытым, ищут, а не выбирают из длинного списка всех магазинов: поле «Найти магазин, чтобы объединить» под подсказанными находит его по мере ввода — по названию, по названию в банке и по-русски для латиницы, — и найденный объединяется одной кнопкой. Объединение идёт без перезагрузки страницы, а запрос остаётся, так что несколько найденных объединяются подряд.
44. Все желания в одном месте: звёздочки на вкладке «План» открывают «Желания», где видно, как разложено каждое желание — откуда его деньги, сколько и когда покупка, — и где план отменяют или меняют. Переключатель «Карточки / Месяцы» показывает желания карточками или деньги всех планов по месяцам. Прототип с тремя видами лежит в ветке `prototype/wish-list`; пользователь выбрал B и C вместе.
