Ты ведёшь Android-приложение бюджета. Оно — то же приложение, что для iPhone, на Kotlin, Jetpack Compose и Glance: тонкий клиент `/api` (`src/web/api.ts`), который раскладывает JSON сервера и сам ничего не считает. Экран за экраном оно повторяет `ios/Budget`: Swift-файл и Kotlin-файл называются одинаково (`HomeView.swift` → `HomeScreen.kt`), части дизайна тоже (`LilacRow` в `Design.swift` и в `Design.kt`). Телефон пользователя — iQOO I2507 на Android 16 (серийный `10AG3919KK0021P`), на «Рабочем» сервере `https://budget.gang.su`.

Правила проекта — общение, отчёт, данные, ситуации экрана, мерж — в CLAUDE.md, он у тебя в контексте. Здесь только то, что касается Android.

Где что описано:

- Что показывает каждый экран и чем Android отличается от iPhone — README, «Приложение для Android»; экраны iPhone — «Приложение для iPhone».
- Файлы приложения — README, «Устройство», строка `android/app/src/main/java/ru/apukhtin/budget`.
- Что сделано и что осталось — `android/TASKS.md`.

## Порядок работы

1. **Прочитай.** Swift-файл экрана целиком, его раздел в README и Kotlin-файл. Готово, когда ты можешь назвать каждое поле API, которое экран показывает, и каждое действие, которое он отправляет.
2. **Реши ситуации экрана** по «Ситуативной иерархии» CLAUDE.md, если правка меняет, что на экране главное.
3. **Сделай.**
   - Данные экран берёт через `Screen<T>("путь", query)`: так у него есть сохранённая копия, пилюля без сервера и обновление жестом вниз. Изменения уходят через `session.send(...)` или `rememberFormSender()`.
   - Собирай из частей `Design.kt`. Части, которой нет, переноси из `ios/Budget/Design.swift` в `Design.kt` под тем же именем.
   - Лист — `LilacSheet` и `BudgetSheet` в `HomeScreen.kt`, страница внутри вкладки — стек маршрутов, как `HomeRoute`, назад — `PageBar` и системная кнопка «Назад». Иконки веба — `WebIcons`, SF Symbols — похожие Material-иконки.
   - Новое поле API — в `Models.kt`: nullable или со значением по умолчанию, если старый сервер его не шлёт, обязательное — если шлёт всегда. Новый экран API — ещё в `ios/fixtures.ts` и `FixturesTest.kt`.
   - Экран, который есть на обоих телефонах, меняй на обоих: iPhone-часть по правилам CLAUDE.md «Приложение для iPhone».
4. **Проверь.**
   - `make android-check` (входит в `make check`): модели читают все экраны API, приложение собирается.
   - Свой сервер на порту 4340 и выше на снимке баз телефона (`make pull-data`), затем `android/screens.sh http://localhost:<порт> <scratchpad>/shots`. Каждый новый экран добавь в этот скрипт. Для сравнения те же экраны iPhone: `ios/screens.sh http://localhost:<порт> <scratchpad>/ios`.
   - Готово, когда каждый изменённый экран ты видел на снимке и он сходится с iPhone.
5. **Поставь на телефон.** `make android-install`, если телефон на кабеле; потом `android/screens.sh phone <scratchpad>/phone`. Телефона нет на кабеле — так и скажи пользователю.
6. **Запиши.** README «Приложение для Android» и «Устройство», `android/TASKS.md`, затем `make check`. Мерж — только по слову пользователя, порядок в CLAUDE.md.

## Грабли

### Код

- Запросы идут только через `ApiClient`: он уводит и запрос, и чтение ответа с главного потока. Ответ, прочитанный на главном, Android обрывает `NetworkOnMainThreadException`.
- Сервер шлёт поля строки и поля её вида одним объектом. Модели с `row` читаются через `FlatRow` и `@KeepGeneratedSerializer`, как `Expense` в `Models.kt`. Поле `when` в Kotlin — `@SerialName("when") val time`.
- `Screen` внутри листа или внутри уже прокручиваемой страницы — с `refreshable = false`, иначе его экран ошибки прокручивается внутри прокрутки и падает.
- Поле, которому сервер или экран переписывает текст (сумма с разрядами `Money.typing`), берёт значение через `typedValue`: тогда курсор после переписывания встаёт в конец.
- Все вкладки живут одновременно: открытая лежит сверху (`zIndex`) и ловит касания пустым `pointerInput`, скрытые прозрачны и без семантики. Новая вкладка встаёт в этот же `forEach` в `BudgetApp.kt`.
- Выбор даты — Material `DatePicker` под `LocalConfiguration` с русской локалью, иначе он на языке телефона.
- Общие объекты — через `CompositionLocal`: `LocalSession`, `LocalOpenShop`.
- Версии сборки в `android/gradle/libs.versions.toml` закреплены вместе: AGP 8.13, Kotlin 2.2, Compose BOM 2025.12, Glance 1.1. Новая версия одной из них тянет `compileSdk` и остальные — поднимай их вместе и собирай.

### Эмулятор и телефон

- Перед своим `./gradlew`, `adb`, `emulator` — `. android/env.sh`: там `JAVA_HOME` и пути SDK. Нет инструментов — `android/setup.sh`.
- Эмулятор видит Mac как `10.0.2.2`; приложение берёт сервер из запуска `-e server http://10.0.2.2:<порт>` и только с этого адреса.
- Демо-данные с тратами «Ждут разбора»: копия `src` и `package.json` в папку scratchpad без `data/`, `PORT=… node src/web/server.ts` в ней. У пользователя всё разобрано, очередь проверяется только так.
- Нажатия ищи по тексту или по `testTag` (они видны UI Automator как `resource-id`; лист — отдельное окно, там это включено в `LilacSheetFrame`). Строку жми слева, по значку: в середине может быть «Принять», которое меняет данные. Ручные `adb`-цепочки пиши для `/bin/sh`: zsh не делит `$b` на слова.
- `uiautomator dump` возвращает пустое сразу после запуска: дождись текста на экране, как `wait_for` в `android/screens.sh`.
- `adb shell input text` набирает только латиницу: тестовые названия латиницей, созданное в проверке удаляй.
- Записи при проверке — только на копии баз; что изменил, верни. Телефон смотрит в VDS, его данные проверка не трогает.
- Телефон: экран уже эмулятора (около 392 dp против 411), длинные строки сжимаются раньше. Погасший экран даёт чёрные снимки — на прогон `adb shell svc power stayon usb`, после `adb shell svc power stayon false`. Пока в фокусе поле пароля, снимок экрана телефон не даёт.
- Режим разработчика на iQOO: О телефоне → Информация о версии ПО → 7 раз «Номер версии ПО»; Система → Параметры разработчика → «Отладка по USB».
- Токен VDS вводит пользователь (CLAUDE.md); команда, которая набирает его на телефоне, не показывая, — в README «Приложение для Android».

### Виджеты

- Glance не рисует сам: кольцо, столбики, линию, привидение и иконки `WidgetArt` рисует на картинках в масштабе 2 к dp.
- Виджеты всегда светлые: Android не перерисовывает картинки при смене темы.
- Сервер они читают раз в полчаса и сразу после `Session.changed()`. Все пять обновляются вместе, поэтому `WidgetLoader` читает сервер один раз под `Mutex`, остальные берут его ответ.
- Посмотреть на эмуляторе: `adb shell am start -n ru.apukhtin.budget/.MainActivity -e pin week` (`today`, `savings`, `payment`, `extras`), затем «Add to home screen». Лаунчер ставит виджет на страницу, где есть место. Сбросить рабочий стол эмулятора: `adb shell pm clear com.google.android.apps.nexuslauncher`.
